【任務二：重設環境 data/regime.json】

網站所有事件的衝擊分數都乘上這五格環境放大係數，設錯的話整份排序都是錯的。
使用者不會每個月記得回來調，所以由你維護。

先讀這一週 data/reviews.json 裡的複盤結論，特別是判讀為「方向背離」的那幾筆——
那代表環境可能已經切換，是最強的訊號。再對照當下的市場資料，重設這五格：

  shock  衝擊來源      -1 成長主導 / 0 混合 / 1 通膨主導
         判準：強勁就業數據當天，股債是同向跌還是股漲債跌？同向跌＝通膨主導。
  infl   通膨離目標距離 0 貼近 / 0.5 偏離 0.5-1pp / 1 偏離 >1pp
         判準：最新核心 PCE 年增率減 2%。
  pivot  政策轉折距離  0 明確觀望 / 0.6 方向未定 / 1 下次可能動
         判準：下次 FOMC 的 OIS 隱含機率。單一結果 >85% 算觀望，40-60% 算可能動。
  vol    波動定價水位  0 高分位 / 0.4 中位 / 1 低分位（反向）
         判準：VIX 在過去一年的百分位。低於 25 分位就填 1——
         隱含波動低、部位擁擠時，同樣大小的意外會造成更大的實際變動。
  conc   指數集中度    0 分散 / 0.5 偏高 / 1 極度集中
         判準：那斯達克 100 前五大成分股的合計權重。

整個檔案覆蓋寫入：
{"generated":"YYYY-MM-DDTHH:MM:SSZ","asof":"YYYY-MM-DD",
 "basis":"兩三句話說明這五格為什麼是這個值，要寫得出判準與數字",
 "values":{"shock":1,"infl":0.5,"pivot":0.6,"vol":1,"conc":1}}

basis 會顯示在網站的「環境」頁，使用者靠它判斷你設得合不合理，不要寫空話。
如果這週跟上週相比沒有任何一格需要改，就不要動這個檔案，並說明為什麼不改。
使用者如果自己在網站上按過選項，他的設定會蓋過你的，那是刻意的，不用擔心。

【任務三：檢視校正結果】

讀 data/reviews.json，把累積的複盤按事件類型分組，算每一類的
「實際變動 ÷ 當天 sigma」平均值，跟 CAT 裡的基準敏感度 B/50 比。
某一類如果累積六筆以上、而且實際持續偏離基準 30% 以上，
就在 PR 裡提出調整那一類 B 的建議，附上樣本數與計算過程。
不要直接改 B——那是模型參數，要讓使用者看過再決定。
樣本不足六筆就明說「樣本不足，暫不建議調整」。

【任務四：每週一項工程改進，開 PR】

每週只挑一項，做完做好，不要一次動很多地方。改進的優先序照這份路線圖，由上往下做：

  1. 資產曝險係數改成滾動估計。現在 ASSETS 陣列裡的 beta 是寫死的常數
     （那斯達克對長端實質利率 −1.0 之類），那是某個時期的數字。
     改成由 scripts/ 每天跑 60 日滾動迴歸：各資產日報酬對 2 年期殖利率、
     10 年期實質利率、breakeven、風險溢酬代理變數迴歸，寫進 data/betas.json，前端讀它取代常數。
  2. 回測。拿過去兩年的事件日期與實際變動，算衝擊分數十分位對實際變動十分位的 rank IC。
     沒有這個數字，70 分門檻就只是一個看起來合理的猜測。結果寫進 data/backtest.json 並顯示在「資料」頁。
  3. 意外空間。目前公式裡完全沒有共識分歧度這一項，但標題文案有寫。
     找得到經濟學家預測分歧度就用，找不到就用過去八次的意外標準差當代理。
  4. 效能：事件數變多之後 renderYear 是不是變慢了。
  5. 手機上的可讀性與觸控目標大小。

規則：
  - 改動前後都要驗語法：把 index.html 裡的 script 內容抽出來跑 node --check。
  - 一次只改一項，PR 標題格式：weekly: 一句話說明。
  - 任務二的 data/regime.json 可以直接 commit（資料檔），任務三與任務四走 PR。
  - PR 內文要寫：改了什麼、為什麼、怎麼驗證的、有沒有你不確定的地方。
  - 在 data/changelog.json 最前面加一筆紀錄。
