# 舌象 RGB 量測

拍舌頭 → 算出取樣區的 RGB 中位色 → 給出 **B/R 比值**與色度學指標，用來追蹤「青紫舌（瘀血傾向）」的變化。
單檔 HTML，沒有後端，全部在手機瀏覽器本機運算。

網址（GitHub Pages 部署後）：`https://<帳號>.github.io/event-calendar/tongue/`
用 Safari / Chrome 打開 → 分享 → 加入主畫面，就是一支離線可用的 App。

---

## 一、先講結論：0.7 這個閾值不能直接用

未校色的 B/R **量到的主要是光源色溫，不是舌頭**。同一條舌頭：

| 光源 | 大致 B/R（sRGB） |
|---|---|
| 3000K 黃色鎢絲燈 | 0.40 – 0.50 |
| 4000K 一般日光燈 | 0.55 – 0.65 |
| 6500K 冷白 LED／陰天窗邊 | 0.70 – 0.85 |

也就是說，**換一顆燈泡就能讓任何人「變成青紫舌」**。所以這支 App 的設計原則是：

1. 每一筆紀錄都存**未校色的原始 RGB 中位值**；
2. 校色資料是獨立的一層，任何時候換新的校色，**過去所有紀錄自動重算**，不用重拍；
3. 判定閾值可調，而且介面上直接算給你看「以你自己的基線，門檻應該訂在多少」。

所以現在沒有色卡也可以先開始累積資料，色卡到了再回頭校正，資料不會白拍。

## 二、拍攝 SOP（比演算法重要）

- **固定光源**：陰天的窗邊散射光最穩定。不要用閃光燈，不要在正上方光源下拍（舌面會整片反光）。
- **固定時間**：早上刷牙前、空腹。剛吃完東西、喝完熱飲、吃過有色食物（咖啡、莓果、藥丸）都會改變舌色。
- **固定距離角度**：舌頭自然伸出、放鬆平展，不要用力捲或繃緊（用力會讓舌色變深變紫，這是最常見的假陽性來源）。伸舌超過 15 秒也會充血變色，**伸出來就拍**。
- **只框舌質**：取樣橢圓不要框到嘴唇、牙齒。厚舌苔的地方量到的是苔色不是舌質色。
- 舌面與**舌下絡脈**兩種都拍。中醫看瘀血，舌下靜脈的怒張青紫通常比舌面更早出現。

## 三、演算法

**取樣**：橢圓內逐點取樣（上限約 9 萬點），先剔除

- 任一通道 ≥ 250（過曝）
- V > 0.90 且 S < 0.15（鏡面反光）
- V < 0.12（陰影／口腔深處）

再算一次 CIELAB 中位色，把跟中位色 ΔE 超過門檻（預設 26）的點丟掉，**重算中位色**。兩段式讓牙齒、嘴唇、口腔陰影不會把結果拉走。取的是中位數不是平均，對離群值更穩。

**指標**

| 指標 | 意義 |
|---|---|
| `B/R (sRGB)` | 檔案裡 0–255 直接相除，就是最直覺的那個比值 |
| `B/R (線性)` | 去掉 gamma 還原成真實光量後相除，物理上才是藍光／紅光的能量比。數值明顯較低（sRGB 0.70 ≈ 線性 0.43），**兩個閾值不能混用** |
| `b*` | CIELAB 黃藍軸。正＝偏黃紅，負＝真的偏藍。健康舌約 10–20；掉到 5 以下甚至負值才是色度學上真的「發青發紫」。**比 B/R 抗光線變化，建議一起看** |
| `a*`, `h°`, `C*` | 紅綠軸、色相角、彩度 |
| 分區 B/R | 舌尖／舌根／左緣／右緣／舌中，看局部瘀點 |

**品質檢查**：反光佔比、過曝佔比、平均亮度、有效像素數、取樣區的 ΔE 散布。任何一項超標會在結果頁直接標紅，因為爛照片算出來的漂亮數字沒有意義。

## 四、校色

**① 灰卡白平衡（現在就能做）**
拿中性灰卡或白紙，放在跟舌頭同一個位置、同一個光線下拍一張，點一下那塊灰。App 在線性空間算出 R/G/B 三通道增益（von Kries 對角變換），把光源色偏扣掉。**換光源就要重做。**

**② 24 色卡完整校色（買到色卡再用）**
支援 X-Rite / Calibrite **ColorChecker Classic（24 色）**或相同排版的複製品。把色卡跟舌頭放在同一張照片裡拍，依序點四個角落**色塊的中心**：

```
左上（深咖啡膚色）→ 右上（藍綠）→ 右下（黑）→ 左下（白）
```

App 用這四點解一個透視變換（homography），自動定位並取樣 24 個色塊，再用最小平方擬合一個 3×3 色彩校正矩陣，把相機的色偏與通道串擾一起修掉，並回報校正前後跟標準值的平均 ΔE。**校正後平均 ΔE 落在 3–8 算很好，10 以內堪用**；比校正前還大就是點錯角或色卡上有反光。

要買的話買 **ColorChecker Classic Mini** 或 **Passport Photo 2** 就夠了；標準值已內建在 `index.html` 的 `CC24` 陣列，如果你的卡附了自己的量測數據可以直接改那裡。

## 五、怎麼訂出對你有意義的閾值

抄外面的 0.7 沒有臨床根據。正確做法：

1. 先照 SOP 累積 **至少 30 天**的資料，光源與時間固定。
2. 到「紀錄」頁看你自己的**中位數與標準差**——App 會直接算 `中位數 + 2×標準差` 給你，那才是對你有意義的「異常偏藍」門檻。
3. 每次拍的時候在備註寫下當天狀態（經期、睡眠、痛不痛、有沒有瘀青）。之後匯出 CSV，把備註標成 0/1，就能算這個指標對你的敏感度／特異度，甚至畫 ROC 找最佳切點。
4. 買到色卡之後重做一次校色，前面的紀錄會自動重算，基線會更穩。

## 六、限制（重要）

- **這不是醫療器材，不能診斷任何疾病。** 有症狀請看醫師。
- 中醫的青紫舌是整體望診的一環：色相、舌下絡脈、瘀點瘀斑、舌體胖瘦老嫩、舌苔厚薄一起看。這支 App 只量顏色。
- 手機相機的自動白平衡、自動曝光、HDR、美顏／膚色優化都會動到顏色。iPhone 的 Smart HDR 與 Android 的場景優化尤其明顯。可以的話關掉這些，並用「鎖白平衡」按鈕（部分 Android Chrome 支援 `whiteBalanceMode: manual`，iOS Safari 目前不支援）。
- 跨裝置的絕對數值沒有可比性，除非兩支手機都做過 24 色卡校色。
- 所有資料存在瀏覽器 localStorage，清快取或換手機就沒了。重要的話定期匯出 CSV／JSON。

## 七、開發

單檔 `index.html`，沒有建置流程。改完跑自我測試（用合成影像驗證色彩運算，不需要真的照片）：

```bash
python3 -m http.server 8899 &
NODE_PATH=/opt/node22/lib/node_modules node tongue/selftest.js
```

測試涵蓋：已知顏色的 B/R 讀數與反光濾除、存檔與 CSV 匯出、灰卡增益方向與中性還原、改校色後舊紀錄重算、24 色卡擬合矩陣是否 ≈ 已知失真矩陣的反矩陣、sRGB／線性切換、JS 例外與版面溢出。
