# 每日 08:00 · 盤後複盤

每個交易日台北時間早上 8:00 執行。用繁體中文回覆，直接進入重點。

**先讀 `routines/_shared.md`。** 以下只寫這個任務自己的部分。

你負責 `data/reviews.json`。不要動任何其他資料檔。

這個任務的產出是**校正的唯一輸入**。沒有複盤，`CAT` 裡那些基準敏感度就永遠是
別人拍腦袋定的先驗，永遠不會被市場修正。

---

## 第零步 · 閘門

跑 `python scripts/validate_data.py && node scripts/smoke_test.js`，
在你動任何東西之前就失敗的話照 `_shared.md` 第八節處理。

順手移除 `reviews.json` 裡 400 天以前的 items。

---

## 第一步 · 昨天有沒有事件

對照 `data/events.json` 與 `data/curated.json`，確認昨天美股交易時段有沒有這些之一：
CPI、非農、PCE、GDP、FOMC 決議或紀要、ISM、零售銷售、追蹤清單裡任何一檔的財報。

沒有就直接回「昨天沒有需要複盤的事件」，**不要 commit**，結束。

---

## 第二步 · 查數字

每一個事件都要查齊這些：

| 欄位 | 內容 | 備註 |
|---|---|---|
| `cons` | 共識預期 | 註明是哪家的共識 |
| `act` | 實際公布值 | 以第一級官方來源為準 |
| — | **口徑要一致** | `cons` 與 `act` 必須是同一個指標 |
| `z` | 意外的 z 分數 | 找得到歷史標準差才填，沒有就留空 |
| `spx` | 標普 500 當日 % | |
| `ndx` | 那斯達克 100 當日 % | |
| `y10` | 10 年期殖利率變動 bp | |
| `dxy` | 美元指數 % | |
| `gld` | 黃金 % | |
| `sigma` | **當天的一般波動基準 %** | **必填** |

### sigma 為什麼是必填

校正會把實際變動除以 `sigma` 換算成標準差倍數，再跟基準比。

沒有它就只能退回寫死的 0.9%，於是 VIX 30 的月份每件事都會看起來「反應很大」，
校正就會把所有事件類型的基準往上調——但那根本不是事件造成的，是當月本來就震。
而且環境設定裡的「波動定價水位」已經在處理波動環境了，**兩邊會重複計算**。

取值方式：前 20 個交易日日報酬的標準差，或當天的 VIX 除以 16。兩者取得到哪個用哪個，
在 `memo` 註明你用的是哪一種。

數字一律填**純數值字串**，正負號要帶（`"-0.9"`、`"+6"`），不要加單位、不要加 %。
閘門會擋非數值。

---

## 第二步之一 · 政策路徑被推了多少

**這是分母端事件複盤的第一件事，不是最後一件。**

`data/policy.json` 已經有每個交易日的完整升降息定價，網站也已經自動算出
「這個事件當天整條路徑動了幾 bp」並顯示在抽屜裡。**你不用去查、不用填任何數字欄位。**

你要做的是把它讀成一句話寫進 `driver` 或 `memo`：

| 型態 | 怎麼讀 |
|---|---|
| 路徑上移、股票跌、長端升 | 分母端主導。市場把降息拿掉了，估值被壓 |
| 路徑上移、股票漲 | 分子端主導。升息預期來自經濟太強，盈餘上修蓋過折現率 |
| 路徑上移、長端**跌** | 最有資訊量的一種：市場讀成政策失誤，前端升、遠端衰退 |
| 路徑幾乎沒動、股票大動 | 這件事跟利率無關，去找真正的驅動 |
| 路徑大動、股票沒動 | 已經被定價，或有更大的力量壓著 |

寫法舉例：
「聯邦資金期貨隱含路徑當日整條上移，9 月會議的升息機率從 34% 跳到 58%，
年底累計定價從 +23bp 走到 +36bp（約 1.45 碼）；同時 10Y 也升、股票跌，
是純分母端的鷹派重定價，不是成長預期上修。」

**沒有政策路徑資料的日子**（序列起點之前的事件）就直接說沒有，
不要用網路上別人講的機率去補——那些數字查不到出處、口徑也對不上。

---

## 第二步之二 · 抓出關鍵驅動分項

總體數字對了不代表市場買單。**每個事件真正推動價格的往往是某一個分項**，
把它找出來寫進 `driver`，一句話講清楚是哪一項、多少、為什麼是它。

| 事件 | 常見的真正驅動 |
|---|---|
| CPI | 核心服務扣房租（supercore）、房租分項的月增動能 |
| 非農 | 平均時薪年增率、前兩個月的修正幅度、勞動參與率 |
| PCE | 核心月增的三個月年化率 |
| FOMC | 點陣圖中位數移動幾碼、長期中性利率有沒有動、聲明稿改掉的形容詞 |
| ISM | 新訂單與客戶端存貨的差、支付價格 |
| 財報 | 下季指引、關鍵分項營收、毛利率、資本支出 |

同時要講清楚**這次走的是分子端還是分母端**。同一份數據在不同環境會走不同端：
非農強勁在成長主導是分子端利多、在通膨主導是分母端利空。

例：非農總數 +55K 符合預期但股債同跌，`driver` 就寫
「平均時薪年增 4.1% 高於預期 3.8%，且前兩月上修 +40K，市場讀成薪資通膨黏性」。
沒有這一欄，複盤只是一堆對得上或對不上的數字，看不出為什麼。

## 第二步之三 · 事件當下市場怎麼讀

事件公布後**立刻**去搜尋市場上的說法，收 3 到 5 則寫進 `views`。
這一步的價值在於保存「當時大家怎麼想」——事後回頭看，共識錯在哪裡比誰說對了更有用。

```json
"views":[
 {"tone":"鷹","t":"薪資年增回升到 4.1%，年內降息空間可能只剩一次","who":"某投行首席經濟學家","src":"Reuters 2026-09-04"},
 {"tone":"鴿","t":"前兩月大幅下修才是重點，趨勢動能已經破 100K","who":"某研究機構","src":"CNBC"},
 {"tone":"中性","t":"數字混雜，市場等 9/16 點陣圖才會定方向","who":"某券商策略團隊","src":"Bloomberg 搜尋摘要"}]
```

規則：
- `tone` 只能是 `鷹`／`鴿`／`偏多`／`偏空`／`中性`，閘門會擋其他值。
- `who` 必填。**沒有出處的市場說法不要收**，那跟你自己編的沒有區別。
  記不得是誰說的就寫機構名稱，連機構都說不出來就不要收那一則。
- 要**收互相衝突的說法**。三則都同一個方向的話，你八成只讀了同一篇的轉載。
  刻意去找反方，那才是有資訊量的。
- 這些是說法不是事實。網站上會標明「這些是事件當下市場上的說法，不是事實也不是共識」。
- 論壇與社群（Reddit、PTT、X）屬第四級，只能當線索。要收就必須找得到具名機構或
  署名分析師的原始說法，否則不要放進 `views`。

---

## 第三步 · 判讀

先確認反應是否符合傳導邏輯：物價數據高於預期應推升殖利率、壓低長天期成長股；
就業強勁在通膨主導環境是利空、在成長主導環境是利多。

然後套四象限，明確講出是哪一種：

| 象限 | 判讀 | 含意 |
|---|---|---|
| 意外大、反應大 | 環境確認 | 傳導鏈有效，同類事件可以照分數配置 |
| 意外大、反應小 | 已被定價 | 資訊提前洩漏，調降這類型權重 |
| 意外小、反應大 | 部位而非資訊 | 擁擠部位平倉，均值回歸機率高 |
| **方向背離** | **環境可能切換** | 資訊量最高的一種 |

判到「意外小、反應大」時，**優先懷疑進了正回饋**（見 `_shared.md` 一之三）：
那不是基本面在動，是部位在動，而部位會自己餵自己。
在 `memo` 裡講明你認為是負回饋（自我修正、均值回歸機率高）還是正回饋
（自我強化、趨勢或崩盤的起點），以及依據是什麼。
這兩者的後續完全相反，混為一談等於沒判讀。

判讀是「方向背離」時，額外說明環境設定的哪一格應該改、改成什麼，
**並把這個結論寫進該筆的 `memo`**。每週任務會讀這些 memo 去更新 `data/regime.json`，
那是你跟環境設定之間唯一的傳話管道，寫得含糊它就用不上。

---

## 第四步 · 回頭檢討 pxd

讀 `data/priced.json`，找出這個事件當初被估的 `pxd`：

- 標成 0.85 已定價、結果卻大幅波動 → 當初高估了定價程度，說明是哪裡判斷錯
- 標成 0.3 沒被定價、結果卻沒動 → 反過來

**這是讓明天的定價估計變準的唯一回饋管道，不要跳過。** 就算判斷是對的也要說一句「估得準」。

---

## 口徑必須跟事前的共識對得起來

網站會拿 `cons` 與 `act`（優先用 `z`）判定「高於預期／符合預期／低於預期」，
直接標在事件卡與抽屜上。所以這兩欄的口徑必須跟 `data/priced.json` 裡
事前寫的 `cons` 是同一個東西。

**寫之前先讀 `data/priced.json`**，看當初查的是哪個口徑，用同一個。
例如 PCE 事前寫的是核心年增率，複盤就不能填總體年增率——
那樣算出來的意外判定是假的，而且校準會跟著錯。

事前那筆如果沒查到共識，就照你查到的口徑寫，並在 `memo` 註明你用的是哪一個。

## 財報要逐項填實際值

財報事件的 `data/priced.json` 裡會有一個 `metrics` 陣列，是事前查好的各項共識。
複盤時把**同名指標的實際值**填進 `reviews.json` 同一筆的 `metrics`：

```json
"metrics":[{"n":"EPS","cons":"1.20","act":"1.31","unit":"USD"},
           {"n":"營收","cons":"46.5","act":"47.8","unit":"B"},
           {"n":"資料中心營收","cons":"41.0","act":"40.2","unit":"B"}]
```

`n` 必須跟事前那筆**完全相同**，不然併不起來、表格上會變成兩列。
網站會自己算差異百分比並標優於／符合／低於（門檻 1%），你不用算。

指引（guidance）不是數字指標，寫在 `memo` 裡：下季營收指引多少、跟共識比如何。
財報常常是 EPS 與營收都優於預期、但指引砍了所以股價大跌——
沒把指引寫進 memo 的話，複盤看起來會跟股價反應完全對不上。

## 寫入格式

先讀原檔，保留既有 items，同一筆（`date` + `title` 相同）覆蓋，其餘不動。

```json
{"generated":"YYYY-MM-DDTHH:MM:SSZ","items":[
 {"date":"YYYY-MM-DD","title":"必須跟日曆上完全一致",
  "cons":"","act":"","z":"","spx":"","ndx":"","y10":"","dxy":"","gld":"",
  "sigma":"","metrics":[],"driver":"","views":[],"memo":"","asof":"YYYY-MM-DD"}]}
```

`title` 對不上就不會顯示，寫之前先確認名稱。
使用者自己在網站上填過的同一筆優先於你寫的，你不會蓋到他的紀錄。
